The shipped configuration disables the activity journal.

When explicitly enabled, each record is limited to:

- `recordedAt`: an ISO timestamp generated by the runtime;
- `event`: a supported registered hook event name (the default registration has three;
  optional lifecycle events need separate registration and storage opt-ins);
- `tool`: the bounded hook-facing tool identifier, when present;
- `decision`: `deny`, when a guard denied the call.

The journal does not copy command text, prompts, tool arguments, tool responses, output, transcripts, session or turn identifiers, models, permission modes, credentials, working directories, or absolute user paths. The writer rejects unknown record fields and unsafe tool identifiers. Tool identifiers can still reveal installed integrations or information encoded in a custom tool name. Reports contain only aggregate counts.

Writes use only the explicit reviewed `CODEX_MODS_DATA_DIR` selection or native
`PLUGIN_DATA` fallback. The CLI report requires an explicit absolute `--data-dir`; neither component derives a storage path from hook input or the current project. Current and previous journal files are each bounded to 1 MiB. Normal concurrent writes are serialized by a short local lock. Reports create no files or directories: they check the lock and file metadata before and after reading, retry briefly if a writer changes them, and return a busy error if a stable read is unavailable. This provides consistency for cooperating writers, rather than a filesystem transaction.

New data directories use mode `0700` and journal files use `0600`. Existing data directories and journal files must belong to the current user on POSIX systems and must not grant group or other access; the plugin rejects unsuitable permissions instead of changing them. Symbolic links in the data path and hard-linked journal files are rejected. These checks do not defend against another process running as the same operating-system user that actively replaces paths or edits files. Source dev7 uses the reviewed handle/NTFS ACL adapter for Windows journal/state/
selected-export operations. Creation is private at the OS API boundary; existing
unsafe ACLs refuse without repair. Windows dashboard/project/Git/restore paths
remain gated before traversal. Windows mode bits are not privacy evidence. See [Windows storage](windows-storage.md).

Filesystem metadata can still reveal that the plugin was used and when a journal file changed. Anyone with access to the plugin data directory can read its records. Enable it only when that local metadata is acceptable.

## Explicit selected-scope retention (source26)

The POSIX [retention CLI](retention.md) previews only the scope selected by reviewed
private settings, then requires its unchanged fingerprint for explicit cleanup.
No automatic data deletion, sibling-scope discovery, MCP writer or lock reaping.
Both journals remain when any retained record is too recent. Deletion may partially
complete or leave locks after interruption; inspect after stopping writers, do not
retry automatically. Windows refuses before IO. Configured source26 is installed/human-trusted; bounded native hooks/panel/Watch acceptance passed after restart; full lifecycle remains incomplete; no cleanup
of installed production records was performed by this milestone.
