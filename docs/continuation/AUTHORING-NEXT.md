## Bounded implementation objective

Design and implement one coherent extension of authoring for (a) an observation-
only lifecycle component and (b) a bounded metadata-backed owned status component,
using existing host mechanisms and stable reviewable contracts. Choose the narrow
useful representation after source review; do not invent an unrestricted plugin
code generator, promise native slash callbacks or substitute another client.

The intended user can describe a small status/observer mod through the existing
skill, receive disabled reviewable artifacts and synthetic tests, inspect the
actual added read/write/event permissions, validate/replay, then deliberately merge
and install/update. Be precise if either component is an approximation. A new
source schema by itself does not establish a released/native host capability.

1. Preserve the existing notice/deny/replacement output/replay compatibility and
   meaningful tests. Describe at least one useful new component end-to-end; do not
   accumulate disconnected templates or only add documentation.
2. Every generated component starts disabled/unregistered, with explicit access
   delta, defaults/limits, synthetic match/control/malformed fixtures and review/
   installation/removal steps. Observer reception and storage remain separate
   choices. No inherited new data/export/project selection or automatic enrollment.
3. Retain strict bounded schemas, literal rendering, no eval/HTML/script/network,
   arbitrary module loading or dynamic hook shell interpolation. The declarations
   describe template access; they are not an OS sandbox for trusted local code.
4. Output creation must not overwrite existing work/traverse links/escape its
   selected output or publish sensitive fixtures. Review interruption/partial
   output, untrusted text, invalid component combinations and fixed privacy
   diagnostics. Do not broaden Windows writer/authority guards; new unavailable
   Windows paths must refuse before IO, not rely on POSIX mode bits.
5. Validate/replay must not execute fixture commands, write production metadata,
   approve calls, alter permissions/prompts/parent model, make extra model/API
   calls or trust code. The describing skill uses the selected model/usage; local
   deterministic generation/validation/replay makes no added model calls.
6. Provide meaningful contract/output/access/privacy/default-off/bounds and
   integration tests. Keep unit/subprocess/simulated UI vs native evidence distinct.
   Design a concrete harmless native acceptance package/review only after code
   is usable. Preserve installed27 until supported reviewed update. Fresh human
   event/storage selections, trust/restart and any additional model-run usage
