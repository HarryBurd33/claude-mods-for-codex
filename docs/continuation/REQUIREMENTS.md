# Requirements ledger

Assessment date: **2026-10-23**. The full product is **incomplete**. This ledger
supersedes the earlier MVP's exclusions; an earlier implementation choice is
neither proof of host support nor proof that a capability is impossible.

## Reading the ledger

Each row accounts for one requested capability or an independently testable
part of it. **Status describes the assessed mechanism, not product completion.**
`supported` means a documented/released mechanism or locally verified component
exists for the stated target; its implementation and acceptance columns can
still be incomplete. `approximation` means the substitute changes the requested
experience. `unverified` means a material capability or host behavior remains to
be established. `unavailable` means the requested mechanism is absent from the
reviewed public interfaces for the stated scope, not that it can never exist.
`deliberately excluded by policy` records an explicit user/security constraint.
No unimplemented supported row is silently deferred out of scope.

Evidence levels are **D** (official documentation), **S** (public source at a
named release/commit), **A** (this repository's automated test), and **H**
(actual host observation). A schema, source implementation, simulated UI bridge,
or subprocess replay alone is not H. The native proof package is separate from
the production plugin. The first portable proof was installed through CLI163,
its cached files matched the reviewed snapshot and its MCP server appeared in
inventory. However, `plugin/read` reported `hooks: []` and hook inventory did not
include it. Both released CLI versions deliberately skip bundled hooks for the
portable AgentPlugin format. This is a real documentation/runtime discrepancy,
not successful native hook execution. The subsequent **compatibility-only proof
0.0.2** was installed and `hooks/list` showed three trusted hooks after human
review. In the actual desktop session, the exact harmless BEFORE command
produced AFTER, the DENY marker was blocked before execution, and an unrelated
UNCHANGED marker ran unchanged. The real MCP App connected to
`chatgpt 26.1016.62342`; its local button changed 0→1 and explicit **Refresh**
changed retained metadata records 22→29 after real hook activity. These are H
observations of covered tool delivery, fixed rewrite/deny and an owned UI
interaction. They do **not** prove a negative sandbox/permission test, automatic
UI subscription, complete lifecycle/accessibility, SessionStart, or native
Windows. An ephemeral app-server thread/start without a model turn produced no
SessionStart evidence. Record detailed observations in
[TEST-LOG.md](TEST-LOG.md) and update affected rows before each handoff.

**Sol Ultra checkpoint:** source now includes the v2 dispatcher contract, opt-in
exact Bash command replacement, scoped native-hook metadata integration,
read-only project/Git changes adapters and CLI, and a production MCP/dashboard
foundation. The new dashboard has **no live-host acceptance**; its transport/UI
fixes passed independent review and synthetic/integrated checks; native acceptance remains incomplete. The explicit activity watch is
bounded to 30 seconds and must be started by the user; it is not a permanent
subscription. Patch text needs separate explicit opt-in. No context/token/cache
or billing feed was added. Production **0.2.0-dev.1 is not installed**.

A separate **hold proof 0.0.3** was installed and human-trusted. Before its MCP
connection was available, the harmless marker ran: this is observed infrastructure
fail-open behavior. After connection, the actual native hook waited 30 seconds
and denied on timeout. The hold plugin and its dedicated marketplace were then
removed through the supported CLI; proof0.0.2 remains installed. The user
reported answering a form, but an accepted or
declined response with verified human provenance was not established. These
observations do not establish a working human approval flow or production hold.

**Dependency affecting every hook row:** use a compatibility-only package
with `.codex-plugin/plugin.json` and omit the root portable `plugin.json`.
This resolved discovery/trust/covered-tool execution for proof 0.0.2. The
production source is now **0.2.0-dev.1**, with only
`.codex-plugin/plugin.json`; production native installation/execution remains
unverified and requires independent acceptance. A compatibility
overlay beside a portable root does not solve the release loader gate. Portable
MCP packaging remains a valid separate path. The desktop runtime must be checked
independently of these CLI release findings.
