## Reading the ledger

Each row accounts for one requested capability or an independently testable
part of it. **Status describes the assessed mechanism, not product completion.**
`supported` means a documented/released mechanism or locally verified component
exists for the stated target; its implementation and acceptance columns can
still be incomplete. `approximation` means the substitute changes the requested
experience. `unverified` means a material capability or host behavior remains to
be established. `unavailable` means the requested mechanism is absent from the
reviewed public interfaces for the stated scope, not that it can never exist.
`deliberately excluded by policy` records an explicit user/security constraint.
No unimplemented supported row is silently deferred out of scope.

Evidence levels are **D** (official documentation), **S** (public source at a
named release/commit), **A** (this repository's automated test), and **H**
(actual host observation). A schema, source implementation, simulated UI bridge,
or subprocess replay alone is not H. Initial portable-package inventory had no
hooks; compatibility-only packaging subsequently delivered the original native
proof and production dev4. Keep `.codex-plugin/plugin.json` and omit the root
portable manifest on reviewed CLI163/164: the portable loader skips bundled
hooks and root precedence defeats an overlay. Native installed desktop/runtime
must be observed separately from system CLI source findings.

Historical original proof0.0.2 and productionv1 delivered covered rewrite/deny and
owned-panel interaction. One explicitly authorized selected-project native CLI
run later produced SessionStart/PreToolUse/PostToolUse metadata visible in Desk;
that authorization is consumed. Dev4 native results above are later version-
specific observations. Dev5 preview/observer source does not inherit them.

Old hold0.0.3 timed out despite a reported form response; disconnected calls
could run. Corrected0.0.4 verified the fixed-marker response paths and was removed.
Human confirmed the affirmative action, but MCP alone does not attest responder
identity. These observations do not establish production enforcement or
fail-closed host infrastructure. Details and exact tests belong in TEST-LOG.md.
