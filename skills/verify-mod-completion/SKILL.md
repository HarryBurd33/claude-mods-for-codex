---
name: verify-mod-completion
description: Verify a claimed Claude Mods milestone or completion against requirements and observed tests before reporting it as done.
---

Map each claim to its target client, OS/version and acceptance test. Read the current requirement ledger and relevant change. Distinguish documented support, released source, automated tests and actual host observations. A schema or mock is not a live result; passing a portable Windows lane is not native Windows compatibility.

Run checks warranted by the change and preserve failures as evidence. Verify installation, loaded cache, human trust and real event/UI handling separately when claimed. Review allow/deny/cancel/timeout/failure behavior, privacy defaults, isolation and teardown where applicable. Use synthetic secrets and harmless commands.

Report implemented, approximation, unsupported and blocked/unverified items precisely. Keep supported unfinished work in scope. Never mark the full product complete from a small usable milestone. Before a model switch save durable sanitized records, upload safe progress, read back the exact remote branch/commit and stop for the human.

This skill uses the selected model and authorized package/workspace reads and test commands. It grants no extra install/publish/network authority, never approves a native call or trusts hooks, and makes no automatic model/API test runs. Private logs/config/paths stay in ignored local records.
